# Echo 产品演进 · 各阶段详细需求与原型 Spec

## Why

演进路线 PRD（`echo-product-evolution/Echo产品演进路线PRD.md`）已明确四阶段路线与需求池（R1.x–R4.x，共 22 条需求），但每条需求目前仍停留在"一句话描述 + 验收标准"层面，工程与设计无法据此直接排期开发；同时缺少可交互的具体原型来对齐产品形态。本 spec 将四阶段需求展开为**可直接交付开发/设计**的详细产品需求文档（统一细化模板，字段级/状态机级），并为每个阶段产出**覆盖全部核心界面与交互路径**的高保真 HTML 原型。

## What Changes

- 阶段一（V2.0 陪伴体验重塑）：详细产品需求文档（R1.1–R1.7）+ 高保真原型
- 阶段二（V2.x 功能闭环补齐）：详细产品需求文档（R2.1–R2.7）+ 高保真原型
- 阶段三（V3.0 从存储到理解）：详细产品需求文档（R3.1–R3.4）+ 高保真原型
- 阶段四（V3.x+ 规模化与商业化）：详细产品需求文档（R4.1–R4.4）+ 高保真原型
- 每份详细 PRD 遵循统一文档模板（见下"文档模板"），逐条需求展开到字段/状态机/异常/埋点/验收
- 每个阶段原型：纯静态 HTML+CSS+vanilla JS、mock 数据、无真实后端、响应式适配、多页面共享同一 App Shell 与导航
- 交付物按阶段存放于 `echo-product-evolution/stageN/`（含 `<阶段>-详细产品需求.md` 与 `prototype/`），与既有路线 PRD 保持一致；不修改 `echo-ai / echo-core / echo-web` 业务代码（纯文档 + 原型交付）

## Impact

- Affected specs: 新增 `echo-evolution-detail`（本 spec）
- Affected code: `echo-product-evolution/` 下新增 `stage1/` `stage2/` `stage3/` `stage4/` 子目录（详细 PRD + 原型）
- 既有 `echo-product-evolution/Echo产品演进路线PRD.md` 保持不变；无既有业务代码改动

## ADDED Requirements

### Requirement: 详细产品需求文档（统一模板）

每阶段详细产品需求文档 SHALL 遵循以下模板结构（文档内逐条需求均按此粒度展开）：

1. 阶段目标、范围边界、本阶段用户故事清单
2. 信息架构：页面清单、页面职责、页面间导航关系
3. 逐条需求（每条含）：
   - 需求背景与产品目标
   - 用户故事（WHEN/THEN 多场景）
   - 界面布局：页面区域划分、组件拆解、每个组件字段级定义（字段名/类型/必填/默认值/校验规则）
   - 交互流程：操作路径步骤化描述
   - 状态机：默认/加载/空/错误/成功/禁用各态样式与文案
   - 异常与边界：超时、断网、并发、幂等、数据一致性、权限
   - 数据模型：涉及的新增/变更字段与关系
   - 埋点：事件名、触发时机、上报字段
   - 验收标准（可量化，含性能阈值）
4. 本阶段跨需求依赖与发布出口标准

#### Scenario: 每条需求均可评审排期
- **WHEN** 工程/设计/测试读取任一需求的章节
- **THEN** 能直接据此拆任务，无需再向产品追问字段、状态或边界
- **AND** 验收标准可量化（页面加载 ≤X、步骤 ≤N、通过率 ≥Y 等）

### Requirement: 阶段一详细产品需求文档与原型

系统 SHALL 提供阶段一（V2.0 陪伴体验重塑）的详细产品需求文档（R1.1–R1.7）与高保真交互原型。

#### Scenario: 文档覆盖需求
- **WHEN** 需求文档成文
- **THEN** R1.1 伙伴大厅 / R1.2 角色人格化 / R1.3 记忆回忆册 / R1.4 空态骨架错误恢复 / R1.5 会话续期 / R1.6 移动端适配 / R1.7 记忆模板引导 全部按模板展开

#### Scenario: 原型覆盖页面
- **WHEN** 用户浏览阶段一原型
- **THEN** 包含页面：伙伴大厅、沉浸式对话、记忆回忆册（时间线）、伙伴人设编辑、会话续期提示弹窗、移动端视图
- **AND** 核心交互可用：切换伙伴、发送消息（流式示意）、浏览/新增回忆、编辑人设并保存、角色切换即时反馈

### Requirement: 阶段二详细产品需求文档与原型

系统 SHALL 提供阶段二（V2.x 功能闭环补齐）的详细产品需求文档（R2.1–R2.7）与高保真交互原型。

#### Scenario: 文档覆盖需求
- **WHEN** 需求文档成文
- **THEN** R2.1 对话记忆管理 / R2.2 主动回忆 / R2.3 全局记忆搜索 / R2.4 分片续传 / R2.5 模型广场 / R2.6 情绪感知 / R2.7 记忆导出 全部按模板展开

#### Scenario: 原型覆盖页面
- **WHEN** 用户浏览阶段二原型
- **THEN** 包含页面：对话记忆管理（L0/L1/L2）、主动回忆（时间线+日历+推送）、全局记忆搜索、情绪感知（对话内可视化）、模型切换、上传进度（含断点续传示意）、记忆导出
- **AND** 核心交互可用：切换对话记忆层级、日历选择回看、关键词搜索、切换模型生效、上传进度展示

### Requirement: 阶段三详细产品需求文档与原型

系统 SHALL 提供阶段三（V3.0 从存储到理解）的详细产品需求文档（R3.1–R3.4）与高保真交互原型。

#### Scenario: 文档覆盖需求
- **WHEN** 需求文档成文
- **THEN** R3.1 记忆洞察 / R3.2 主动关怀引擎 / R3.3 记忆叙事 / R3.4 多角色差异化 全部按模板展开

#### Scenario: 原型覆盖页面
- **WHEN** 用户浏览阶段三原型
- **THEN** 包含页面：记忆洞察（性格画像/兴趣地图/高频话题）、年度回顾叙事（人生时间线）、主动关怀消息、多角色差异化对比
- **AND** 核心交互可用：查看画像、浏览年度回顾、触发主动关怀示意、角色差异切换对比

### Requirement: 阶段四详细产品需求文档与原型

系统 SHALL 提供阶段四（V3.x+ 规模化与商业化）的详细产品需求文档（R4.1–R4.4）与高保真交互原型。

#### Scenario: 文档覆盖需求
- **WHEN** 需求文档成文
- **THEN** R4.1 多端 / R4.2 订阅商业化 / R4.3 生态开放 / R4.4 家庭共享 全部按模板展开

#### Scenario: 原型覆盖页面
- **WHEN** 用户浏览阶段四原型
- **THEN** 包含页面：订阅方案对比与支付流程、数据全量导出、人格模板市场、家庭共享空间
- **AND** 核心交互可用：选择订阅档位、导出数据、浏览模板并应用、添加共享成员

### Requirement: 原型工程规范

每个阶段原型 SHALL 满足以下工程规范：

#### Scenario: 多页面一致性
- **WHEN** 用户在不同页面间切换
- **THEN** 所有页面共享同一 App Shell 与导航（复制粘贴一致的侧边栏/顶栏标记），活跃项按唯一规则高亮
- **AND** 各原型内链接指向真实页面（无死链），无重复 id、无未定义变量、事件均已绑定

#### Scenario: 响应式
- **WHEN** 在 375px–1440px 宽度浏览原型
- **THEN** 布局自适应，核心页面无横向滚动，关键操作可完成

#### Scenario: mock 数据
- **WHEN** 原型运行
- **THEN** 使用统一 mock 数据源，标注"原型示意"，不调用真实后端
